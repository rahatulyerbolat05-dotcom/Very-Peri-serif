# Что действительно сработало, что не сработало

Источник опыта — Very Peri Serif, расширение Instrument Serif, итог технической
фиксации 1.113. Некоторые художественные кандидаты там **оставались открытыми**.
Поэтому этот проект — источник приёмов и регрессий, не доказанный идеальный эталон.

## Уточнение при упаковке опыта

Сравнение native CFF должно учитывать исходную цепочку экспорта. OTF, заново
полученный из принятого TTF, не обязан сохранять команды/хинтинг оригинального
upstream OTF. Строгая проверка правильно отмечает такую разницу; это не повод
отключать её. Для конверсии нужна отдельная проверка геометрического допуска,
шейпинга и честное описание сохранности hints. По возможности сохраняй исходные
native CFF-программы, строя расширение непосредственно на них.

## Организация, которая экономит работу

- Один измеренный `font-model`, карточки глифов и журнал принятых решений вместо
  разрозненных обещаний в чате. У каждой правки есть причина и область.
- Короткий пилот прежде алфавита; группы по общим деталям; редактируемые masters.
- Повторно используемые детали с параметрами стыка; protected regions при сжатии.
- Первым делом targeted regression на жалобу автора, затем весь набор на побочные изменения.
- Разделение формы и позиционирования: сначала стабилизировать рисунок/поля,
  затем kern/marks/функции на фактических экспортируемых контурах.
- Полный обход glyph order и отдельные пути для Regular/Italic/локальных форм.
- Контрольные отрицательные/положительные примеры, повторная сборка и hash-bound приёмка.
- В отчёте явно оставить открытые задачи. Слово «финальный» не стирает технические
  и оптические ограничения, а помощник не должен обещать запуск недоступных приложений.

Фиксированная эстетика проекта — капли, компактность, выбор г/д, степень декоративности,
13° и числовые толщины — сюда не входят как требования. Их заменяет закон нового исходника.
