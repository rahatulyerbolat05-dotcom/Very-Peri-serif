# Кириллица из закономерностей исходного шрифта

Прочитай [полную инструкцию](references/workflow.ru.md) перед построением форм.
Это переносимый процесс работы агента, а не готовая математическая формула
«латиница → кириллица». Не обещай автоматически безупречный дизайн.

## Запуск по одному файлу

Если скилл вызван, а пользователь передал только шрифт, считай задачей:
**сделать редактируемое кириллическое расширение переданного шрифта**, по умолчанию
русский и казахский в предоставленных начертаниях, с сохранением родной латиницы.
Сначала используй контекст: явно заданный иной языковой набор имеет приоритет.
Для владельца этого комплекта профиль автора — `assets/owner-profile.json`;
при передаче комплекта другому владельцу профиль нужно заменить.
Наклон, ширина, рисунок и числа Very Peri Serif не являются настройками по умолчанию.

Найди абсолютный путь каталога этого SKILL.md. Команды ниже выполняются с этим
каталогом как текущим; файлы проекта и входного шрифта задавай абсолютными путями.
Не считай текущий рабочий каталог корнем скилла.

```sh
python -m pip install -r scripts/requirements.txt
python scripts/font_probe.py /absolute/input.ttf --out /absolute/project/reports/intake --license /absolute/OFL.txt
```

Без приложенной лицензии пропусти `--license`: анализ разрешён, но происхождение
и право распространять производную ещё нужно подтвердить. `--license` только
сохраняет предоставленный файл; скрипт не удостоверяет права.
Прочитай `font-profile.json`, открой `native-controls.svg`, затем заполни
`assets/project-template.json` реальными измерениями и доказательствами.
Упомянутые зависимости нужны для инструментов; системные OTS/Chromium отдельно
не устанавливаются этим файлом. Не отмечай их проверки пройденными без запуска.

## Порядок работы

1. Зафиксируй входные файлы и лицензию, набор языков/начертаний, SHA256,
   оси вариативности и существующую кириллицу. Сохрани неизменяемый эталон.
2. Построй измеряемую модель: высоты/овершуты, профиль толщины по направлению,
   пропорции, ось нажима, наклон, контрформы, засечки, входы/выходы, интервалы.
   Отделяй измеренное, выбранное и предположенное.
3. Сделай пилот **н о п и м л д ж з я**, затем остальные группы. Для Italic
   исследуй родной курсив и русскую письменную структуру отдельно от Regular.
4. Работай небольшими партиями. Проверяй каждый результат сам: весь глиф,
   весь переход, увеличения, реальные слова и соседние контрольные буквы.
   Не превращай каждую партию в запрос разрешения; учитывай уже принятые решения.
5. Зафиксируй выбранные редактируемые контуры и метрики как masters.
   Устанавливай их до интервалов/кернинга; не прогоняй повторную полировку после них.
6. Настрой поля с выключенным kern, затем пары и OpenType-функции. Применяй
   [языковые правила](references/letter-grammar.ru.md) и
   [алгоритмы](references/algorithms.ru.md).
7. Проверь сериализованные шрифты всех выдаваемых форматов. Делай отдельные
   технические, геометрические и оптические выводы; открытая очередь не становится PASS.
8. Выпусти исходники, рабочие шрифты, образцы, лицензии/уведомления и контрольные суммы.
   Восстанови сборку из исходников. Не публикуй и не меняй видимость репозитория без
   разрешения на соответствующее внешнее действие.

## Непереговорные ограничения

- Не дорисовывай на глаз то, для чего есть исходный вектор. Сохраняй координатные
  преобразования и опорные точки; хвост и его стык проверяй отдельно.
- Не сжимай целиком букву ради уменьшения ширины: это меняет толщину. Сначала
  меняй расстояния между сохранёнными стойками/спинками и проектируй связи заново.
- Не зеркаль диагонали без восстановления нажима. Не вырезай донор по номинальной
  базовой линии, если его округлая часть должна иметь овершут.
- Не назначай обычную у букве ү. Не делай п/н и т/м одинаковыми в русском курсиве.
- Не исправляй только совпадение касательных в одном узле: исследуй весь переход.
  Не навязывай G2 намеренным углам и переходам к прямым.
- Не меняй родные глифы, hints и поведение латинских функций без отдельного основания.
  Для новой кириллицы используй отдельные имена и якоря, если общий Latin-донор
  иначе получит новое позиционирование.
- Не расширяй допуск ради зелёной проверки. Исключение — только конкретный
  подтверждённый входной случай с неизменной строгой проверкой конечного результата.
- Не называй покрытие кодовых точек полной языковой локализацией. `locl` проверяй
  с реальным языком шейпинга, лигатуры — в фактическом GSUB, не по названию глифа.
- Не наследуй цифры, угол 13°, решения д/г/хвостов, набор ss01–ss09, пороги качества
  или незакрытые приёмки Very Peri как универсальные законы.
- Сохраняй обязательные upstream-уведомления OFL, проверь RFN, не выдумывай
  юридические факты и контакты автора. Приватность не отменяет выданную OFL.

## Переносимые инструменты

- `font_probe.py`: инвентарь, начальная метрическая модель, профили черноты,
  точный снимок входа и векторный образец родных доноров.
- `audit_outlines.py`: весь glyph order, компоненты, закрывающие сегменты,
  квадратики/кубики, кандидаты неровностей; пороги настраиваются по родным глифам.
- `compare_native.py`: строгая проверка унаследованных контуров/хинтинга,
  метрик и доступных образцов HarfBuzz в том же формате контуров.
- `reduce_nodes.py`: анализ/точное удаление математически лишних точек **только**
  по явному списку новых глифов, без сглаживания; неподдержанные ссылки на точки
  блокируют применение. После сериализации перепроверяет весь набор.
- `install_skill.py`: установка этого каталога в другой проект для Claude Code/Codex.
