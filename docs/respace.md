# Пересчёт боковых полей и кернинга · Regular 1.010

`[РЕШЕНИЕ · 17.10.2026]` По просьбе автора кернинг проработан заново. Вывод аудита: в 1.009 более 60% пар
несут ненулевой кернинг и у многих букв поправка систематически одного знака против почти всех соседей.
Это не исключения пар, а ошибка боковых полей (ц щ ң қ Қ: advance держит место под хвост, ү ұ: широкие
стороны). Кернинг, который лечит поля, раздувает таблицу и ломается при отключённом кернинге.

## Метод

1. Базовая сборка без сдвигов (`tools/respace.py --reset`), `tools/optical_kerning.py` пишет для каждой
   пары `additional` (кернинг сверх родного).
2. Модель `kerning(a,b) ≈ r_a + l_b`: сдвиг контура на l и advance на l+r меняет зазор ровно на r_a + l_b.
   Родная латиница и кириллические омоглифы, идентичные латинским, зафиксированы (r=l=0).
3. Ридж-МНК по 76 тыс. парам, вес пары равен корню произведения частот букв в русском; пары, ограниченные
   защитой от столкновений (`collision_limited`), в подгонку не входят: это потолок, а не потребность.
4. Округление до чётных единиц, порог 6, пол бокового поля −20 (у латинских v y x до −14), итог в
   `data/spacing.json`: `dx` (сдвиг контура), `dadv` (изменение advance). Применяется в
   `tools/build_draft_font.py`, начертания и формы не меняются, только положение в ячейке.
5. Вторая сборка пересчитывает кернинг уже по новым полям.

Порядок: `respace.py --reset` → сборка → `respace.py` → сборка.

## Исправления в самом проходе кернинга

Профили зазоров снимались каждой второй строкой растра. Засечка Г, повисающая над верхом з, давала
расхождение до 8 единиц с реальным растром (Гз, Гэ при записанных 10 были 2 и 4). Теперь каждая строка
(`optical_kerning.py`, `Y` с шагом 1); после этого измеренный минимальный зазор совпадает с записанным
для всех проверенных пар.

## Результат (измерено по готовому TTF, HarfBuzz + растр 1000 px/em, все пары букв)

| | 1.009 | 1.010 |
|---|---|---|
| cv зазоров, строчные+строчные, кернинг включён | 0,100 | 0,095 |
| cv, прописная+строчная | 0,094 | 0,091 |
| cv, строчные+строчные, кернинг отключён | 0,188 | 0,120 |
| слипаний (зазор ≤2), кернинг включён | 0 | 0 |
| слипаний, кернинг отключён (строчные+строчные) | 10 | 51 |
| rms требуемого кернинга до / после подгонки | 39 | 19 |

Слипания без кернинга 1.010 относятся в основном к повисающим парам (г+ж, г+у, А+л и подобные), которые
кернинг и должен разводить; при включённом кернинге их нет. Разброс при отключённом кернинге сильно
снизился: шрифт стал ровнее в приложениях, где кернинг выключен.
