# Первый рабочий этап проверки контуров

24 октября 2026. Проверяется опубликованная 1.110. Файлы шрифта и архив выпуска
не изменены; это новый инструмент диагностики, а не новый выпуск с исправленными
буквами. Он реализует первый этап [плана](contour-quality-plan.md).

  локально в современном браузере с поддержкой `DecompressionStream`. Внутри —
  данные, геометрия и шрифты, внешние сетевые запросы не нужны. В этой среде
  Chromium проверяется через локальный HTTP: политика браузера запрещает
  `file://`, поэтому прямое открытие файла здесь не отмечается как проверенное.
- [PDF с выборкой из очереди](specimen/VeryPeriSerif-Contour-Audit-1.110.pdf).
- Увеличения первых выбранных мест: [Regular](img/contour-audit-regular-1.110.svg)
  и [Italic](img/contour-audit-italic-1.110.svg). Это кандидаты для разбора,
  не утверждение, что каждая показанная особенность является ошибкой.
- [Сводка и SHA256 файлов](qa/contour-audit-1.110.json),
  [полная очередь JSON в gzip](qa/contour-audit-1.110.json.gz),
  [проверки детектора](qa/contour-detector-checks-1.110.json) и
  [проверки интерфейса в браузере](qa/contour-audit-browser-1.110.json).
  [Проверка запрета преждевременной приёмки](qa/contour-audit-gate-1.110.json)
  подтверждает ожидаемый отказ при неразобранной очереди и идентичность
  отчётов при повторном расчёте с кэшем.

В GitHub HTML открывается как исходный код; PDF и SVG можно смотреть сразу.
В интерактивном отчёте доступны поиск буквы/имени глифа, начертание, формат,
тип сигнала, приоритет и статус. По умолчанию показана приоритетная группа;
«Все измерения» открывает остальные сигналы. Это порядок просмотра, а не
автоматическое решение о допустимости остальных мест. Режим «Атлас всех форм»
содержит и формы без сигналов. В карточке можно сопоставить фактические
TTF/OTF/WOFF2 и посмотреть всю букву, увеличение, управляющие и кривизну.

## Что реализовано

`tools/contour_geometry.py` читает линии, квадратичные и кубические кривые через
независимый `BasePen`. Восстанавливаются неявные точки и трансформированные
компоненты. В TTF число прочитанных контуров сверяется с таблицей `glyf`.
Отсутствующий компонент, незавершённое чтение или ошибка геометрии дают явную
ошибку отчёта. Заодно исправлен пропуск контуров только с off-curve точками
в старом `polish_audit.segments`.

Обнаруживаются:

- стыки с углом от 1,5° включительно до 180°, без старой верхней границы 12°
  и без исключения коротких соседних сегментов;
- скачки аналитической кривизны при совпадающем направлении касательных;
- волны через несколько сегментов, включая смены знака через нулевую кривизну,
  с проверкой масштабов 4/12/32/80 единиц при UPM 1000;
- короткие и нулевые сегменты, разрывы, неопределённые касательные,
  нулевые производные на концах и остановки внутри кривой;
- отклонения почти прямого участка и возможные самопересечения внутри контура.

Кривые адаптивно разбиваются с геометрическим допуском 0,035 единицы.
Самопересечения определяются по полученной полилинии и требуют подтверждения
на исходных кривых. Почти прямой участок также является предположением для
просмотра, а не указанием принудительно выпрямить оптическую кривую.

Сигналы объединяются по расстоянию вдоль одного контура. Близкие ветви разных
частей буквы не склеиваются только из-за близких координат. Точные повторения
геометрии используют одну диагностику с полным списком связанных глифов;
переводы контура сохраняются отдельно. Формы, немного изменившиеся при CFF,
не выдаются за точные копии TTF. WOFF2 дополнительно сверяется с таблицами TTF.

В этих шести файлах прочитаны все 3048 записей глифов: 1016 глифов двух
начертаний, каждый в трёх форматах, всего 5805 контуров. Ошибок чтения нет.
Имеются 1770 непустых форм с учётом различий экспортной геометрии.

Сканер сохраняет и слабые измерения: получилось 50 642 места, из которых
275 имеют приоритет просмотра от 60. **Это не количество испорченных мест.**
В список входят обычные углы засечек, допустимые скачки кривизны квадратичных
кривых и сигналы на одной букве в разных экспортных геометриях. Точность
классификации художественных дефектов ещё не измерена на большом размеченном
наборе; уменьшать очередь за счёт молчаливого допуска нельзя.

Первыми для предметного разбора выделены стыки хвостов курсивных ц/щ/ң:
срабатывания на возможные самопересечения присутствуют и в TTF, и в OTF.
Ц и щ используют одинаковую геометрию проблемного стыка, поэтому расследовать
их нужно как общую конструкцию. Наличие сигнала ещё не заменяет решения
о форме и проверки точного места пересечения кривых.

## Проверка самого инструмента

17 автоматических проверок проходят. Они охватывают старые границы углов,
короткие стыки, неявные точки, компоненты, замыкание и смену начала контура,
обратный обход, гладкие волны, масштабы/повороты, чистые контрольные кривые,
вырожденности и устаревание решений о приёмке.

Историческая регрессия использует реальный опубликованный контур я 1.106:
детектор ловит волну ножки, ранее отвергнутую автором; в выпуклой замене текущей
версии эта волна отсутствует. Контрольные синтетические примеры — проверка
конкретных свойств, не статистическое доказательство отсутствия пропусков.

## Как воспроизвести и принимать

После установки зависимостей репозитория:

```sh
make contour-audit
make BROWSER=1 contour-audit
```

Повторный прогон использует локальный кэш `build/contour-audit/geometry-cache.json.gz`.
Ключ включает геометрию, исходник детектора, пороги и версии библиотек. После
изменений старые результаты автоматически не используются. Удаление кэша
даёт полный повторный расчёт.

Решения хранятся в `data/contour-review.json`. Сейчас реестр пуст: автоматических
оптических допусков нет. Для конкретного места нужны его ID, `geometry_sha256`,
`detector_sha256`, статус `intentional` / `defect` / `fixed_pending_recheck`
и непустое объяснение. Пример структуры записи:

```json
{
  "decisions": {
    "ID_ИЗ_ОЧЕРЕДИ": {
      "geometry_sha256": "ХЕШ_ФОРМЫ",
      "detector_sha256": "ХЕШ_ДЕТЕКТОРА",
      "status": "intentional",
      "reason": "Конкретная причина сохранения этого угла после просмотра"
    }
  },
  "forms": {}
}
```

Просмотр целых форм фиксируется отдельно в `forms` по ID из полной очереди,
с теми же хешами, статусом `reviewed` и объяснением. Допуск всех сигналов не
подменяет просмотр буквы целиком. Старые решения с несовпадающими хешами
попадают в отдельный список устаревших и не дают допуска.

```sh
python3 -I tools/contour_audit.py --require-reviewed
```

Эта команда должна завершаться ошибкой, пока остаются ошибки разбора,
неразобранные/подтверждённые неисправленные места или непросмотренные формы.
Обычный успешный прогон означает лишь успешное создание отчёта. Эта новая
оптическая очередь пока не встроена как обязательный барьер старого выпуска:
существующие сборочные проверки и контроль принятых SHA256 не заменяются.

## Что остаётся

Далее — разметка и уточнение приоритетов по реальному визуальному просмотру,
проверка межконтурных наложений и толщины штрихов, разбор хинтинга и растра,
затем исправления общих конструкций партиями и повторная приёмка. Отчёт уже
проверяет геометрию каждого формата, но ещё не выполняет количественное
сопоставление всех соответствующих участков TTF/CFF по производным.

Полный ручной просмотр 1770 форм, оптическая приёмка всех находок, нативные
Windows/macOS и физическая печать не выполнены и не отмечаются как пройденные.
